# Mini CRM для заявок агентства

Простая CRM, в которую лиды попадают сами:

| Канал | Как работает | Источник в CRM |
|---|---|---|
| Telegram-бот | `/start` → имя → контакт → услуга → запрос. Выбранная услуга становится тегом лида | 🤖 Бот |
| Обычный Telegram | Личный аккаунт подключается к боту через **Telegram Business → Чат-боты**. Первое входящее сообщение от человека создаёт лида, следующие сообщения добавляются в его историю | 💬 Telegram |
| Вручную | Кнопка «+ Новый лид» в веб-интерфейсе | ✍️ Вручную |

Теги: создаются в сайдбаре, назначаются лиду при создании или в карточке. Клик по тегу показывает лидов с этим тегом. Есть фильтры по источнику и статусу и поиск.

## Что реализовано по заданию

| # | Пункт задания | Статус | Как проверить |
|---|---|---|---|
| 1 | Заявки из Telegram-бота | ✅ Реализовано | Напишите боту `/start` и пройдите анкету. Лид появится в CRM с источником «🤖 Бот» и тегом выбранной услуги |
| 2 | Подключение обычного Telegram | ✅ Реализовано, ⚠️ **нужен Telegram Premium** | Подключите аккаунт по [инструкции](#настройка-telegram) и напишите на него с другого аккаунта. Лид появится с источником «💬 Telegram», а следующие сообщения попадут в историю в карточке лида |
| 3 | Ручное добавление | ✅ Реализовано | Кнопка «+ Новый лид» в веб-интерфейсе |
| 4 | Теги | ✅ Реализовано | Создайте тег в сайдбаре и назначьте его лиду при создании или в карточке. Клик по тегу в сайдбаре показывает только его лидов |

> **Про пункт 2.** Функционал реализован полностью, но работает на официальном Telegram Business API: личный аккаунт подключает бота в *Настройки → Telegram для бизнеса → Чат-боты*. Подключение чат-бота к аккаунту — функция Telegram Business, поэтому у подключаемого аккаунта должна быть подписка **Telegram Premium**. Без Premium подключить аккаунт нельзя, остальные пункты работают без ограничений.
>
> Подключить аккаунт без Premium можно через userbot (MTProto, Telethon). Мы сознательно отложили этот вариант: для него нужно хранить сессию с полным доступом к аккаунту, а такой способ подключения не является официальным. Подробнее — в [наброске продукта](docs/product.md).

## Стек

FastAPI · PostgreSQL · SQLAlchemy 2 (async) · Alembic · aiogram 3 · uv · Docker Compose. Фронтенд — одна страница на чистом JS, её отдаёт сам FastAPI.

## Архитектура

```
app/
├── core/                  # инфраструктура, ничего не знает о предметной области
│   ├── config.py          # настройки (pydantic-settings, .env)
│   ├── db.py              # engine, Base, unit of work (session_scope)
│   ├── repository.py      # базовый generic-репозиторий (DRY)
│   ├── exceptions.py      # доменные ошибки → HTTP-коды
│   └── security.py        # HTTP Basic для UI и API
├── modules/               # предметные модули: models → repository → service → router
│   ├── tags/              # теги и таблица связи lead_tags
│   └── leads/             # лиды, сообщения, все сценарии поступления лидов
├── telegram/              # транспорт Telegram (aiogram) — тонкий слой над LeadService
│   ├── handlers/application.py  # анкета бота (FSM)
│   ├── handlers/business.py     # подключённый личный аккаунт (Business API)
│   ├── middlewares.py     # одна транзакция БД на апдейт + внедрение LeadService
│   ├── __main__.py        # режим polling (отдельный процесс, compose)
│   └── webhook.py         # режим webhook (внутри FastAPI, Render)
├── web/static/            # веб-интерфейс
└── main.py                # сборка FastAPI-приложения
```

Принципы:
- **Слои.** Router и handler только переводят HTTP/Telegram в вызовы сервиса. Бизнес-логика живёт в сервисах, SQL — в репозиториях. Сервисы бросают доменные ошибки и не зависят от транспорта, поэтому один и тот же `LeadService` используют и API, и бот.
- **Зависимости собираются в одном месте** (`modules/*/dependencies.py`). Модуль `leads` зависит от `tags`, обратной зависимости нет.
- **Транзакция = запрос / апдейт.** Коммит делает `session_scope`, сервисы вызывают только `flush`.

## Быстрый старт (Docker Compose)

```bash
cp .env.example .env
```

Заполните в `.env` поля `BOT_TOKEN`, `POSTGRES_PASSWORD` и `ADMIN_PASSWORD`, затем:

```bash
docker compose up -d --build
```

Откройте http://localhost:8000 (логин и пароль — `ADMIN_USERNAME` / `ADMIN_PASSWORD`). Если порт занят, задайте `APP_PORT` в `.env`.

Сервисы compose:
- `db` — Postgres 16 с healthcheck;
- `api` — при старте применяет миграции (`alembic upgrade head`), затем отдаёт веб-интерфейс и REST API (`/docs` — Swagger, тоже под паролем);
- `bot` — Telegram-бот в режиме long polling, стартует после того, как `api` прошёл healthcheck.

## Деплой на Render

Render не запускает `docker-compose.yml`, поэтому для него всё собрано в один бесплатный web-сервис и бесплатную базу Postgres. Конфигурация лежит в [`render.yaml`](render.yaml).

1. Запушьте репозиторий на GitHub.
2. В Render: **New → Blueprint** → выберите репозиторий. Render создаст базу `crm-db` и web-сервис `crm-service`.
3. На первом деплое Render попросит ввести `BOT_TOKEN` и `ADMIN_PASSWORD`.
4. После деплоя CRM будет доступна по адресу `https://crm-service-xxxx.onrender.com`. HTTPS Render выдаёт сам.

Чем Render отличается от compose:
- **Бот работает через webhook** (`BOT_MODE=webhook`), а не через polling. При старте приложение само регистрирует webhook на `https://<домен>/telegram/webhook`, домен берётся из `RENDER_EXTERNAL_URL`. Запросы к webhook проверяются по секретному заголовку `X-Telegram-Bot-Api-Secret-Token`.
- **Адрес базы** Render отдаёт в формате `postgresql://…`. Приложение само переводит его на драйвер asyncpg.
- **Миграции** применяются при каждом старте контейнера.

Ограничения бесплатного плана:
- Сервис засыпает после 15 минут без входящих запросов. Первый запрос после сна, в том числе сообщение боту, обрабатывается примерно 30–60 секунд. Сообщения не теряются: Telegram повторяет доставку.
- Если сервис заснёт посреди анкеты, состояние анкеты сбросится (оно хранится в памяти), и пользователю придётся начать с `/start`.
- Бесплатная база Postgres удаляется через 30 дней после создания.

> Один токен — один способ получения обновлений. Если бот развёрнут на Render, не запускайте с тем же токеном `docker compose` локально, и наоборот. Polling-бот при старте снимает webhook, после этого Render перестанет получать сообщения до следующего перезапуска сервиса.

## Настройка Telegram

1. **Бот.** Создайте бота в [@BotFather](https://t.me/BotFather) и положите токен в `BOT_TOKEN`.
2. **Подключение обычного Telegram.**
   - В @BotFather: *Bot Settings → Business Mode → Turn on*.
   - В аккаунте, который нужно подключить: *Настройки → Telegram для бизнеса → Чат-боты*. Укажите `@ваш_бот` и выберите чаты, к которым у бота будет доступ.
   - Бот пришлёт подтверждение «Telegram подключён к CRM». После этого входящие сообщения клиентов становятся лидами, а ответы владельца аккаунта игнорируются.
   - ⚠️ Подключение чат-бота к аккаунту — функция Telegram Business, для неё нужен Telegram Premium.

## Локальная разработка

```bash
uv sync
```

В `.env` укажите `POSTGRES_HOST=localhost`, затем примените миграции:

```bash
uv run alembic upgrade head
```

```bash
uv run uvicorn app.main:app --reload
```

```bash
uv run python -m app.telegram
```

Новая миграция после изменения моделей:

```bash
uv run alembic revision --autogenerate -m "describe change"
```

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/leads?tag_id=&source=&status=&q=` | список лидов с фильтрами |
| POST | `/api/leads` | создать лида вручную (`tag_ids` — опционально) |
| GET / PATCH / DELETE | `/api/leads/{id}` | карточка с историей сообщений / изменить / удалить |
| POST / DELETE | `/api/leads/{id}/tags/{tag_id}` | назначить / снять тег |
| GET / POST | `/api/tags` | теги со счётчиком лидов / создать |
| DELETE | `/api/tags/{id}` | удалить тег (с лидов он снимается) |
