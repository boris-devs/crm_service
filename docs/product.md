# Mini CRM для заявок агентства — набросок продукта

## Проблема

Небольшое агентство (веб, реклама, SMM) получает заявки сразу из нескольких мест: бот на сайте, личные Telegram менеджеров, звонки и рекомендации. Заявки теряются в переписках, никто не видит общей картины, непонятно, кто ответил клиенту и откуда пришёл лид. Полноценные CRM (amo, Bitrix) для команды из 3–10 человек избыточны: их долго настраивать и дорого содержать.

## Для кого

- **Владелец / аккаунт-менеджер агентства**: видит все входящие заявки в одном списке и сортирует их тегами (услуга, приоритет, «горячий»).
- **Клиент агентства**: оставляет заявку в Telegram за минуту, без форм на сайте.

## Как это работает

```
 Клиент ──► Telegram-бот (анкета: имя → контакт → услуга → запрос) ──┐
                                                                     │
 Клиент ──► личный Telegram менеджера ──(Telegram Business)──► бот ──┤──► LeadService ──► PostgreSQL
                                                                     │          ▲
 Менеджер ──► веб-интерфейс «+ Новый лид» ──► REST API ──────────────┘          │
                                                                                │
 Менеджер ◄── веб-интерфейс: список, фильтр по тегу/источнику/статусу, карточка ─┘
```

- Все три канала проходят через один сервис `LeadService`, поэтому правила создания лида одинаковы для всех.
- Бот: анкета на FSM. Услуга выбирается кнопкой и **сразу становится тегом** лида.
- Обычный Telegram: аккаунт подключается к боту через Telegram Business (*Настройки → Telegram для бизнеса → Чат-боты*). Первое сообщение от нового человека создаёт лида, остальные копятся в его истории. Ответы самого менеджера в CRM не попадают.
- Веб-интерфейс обновляется каждые 10 секунд, поэтому лиды из Telegram появляются без перезагрузки страницы.

## Что входит в MVP

- Три канала поступления лидов: бот, подключённый аккаунт, ручной ввод.
- Лид: имя, контакт, запрос, источник, статус (новый / в работе / успех / отказ), история сообщений из Telegram.
- Теги: создание с цветом, назначение и снятие, счётчик лидов, фильтр по тегу.
- Поиск, фильтры по источнику и статусу, редактирование и удаление лида.
- Доступ по логину и паролю (HTTP Basic), запуск одной командой через `docker compose`.

## Сознательно за скобками

- **Ответ клиенту из CRM.** Пока это только приёмник заявок, а переписка идёт в Telegram.
- **Пользователи и роли, назначение ответственного.** На старте одна общая учётка.
- **Уведомления менеджеру о новом лиде, воронки, аналитика, импорт и экспорт.**
- **Подключение аккаунта без Telegram Premium** (userbot через MTProto/Telethon). Выбрали официальный Business API: он не нарушает правил Telegram и не требует хранить сессию аккаунта. Цена этого решения — нужна подписка Premium.
- **Устойчивость FSM к рестартам.** Состояние анкеты хранится в памяти; Redis подключается одной строкой, когда понадобится.
- Медиафайлы из сообщений: в историю записывается подпись или тип вложения, сам файл не сохраняется.
