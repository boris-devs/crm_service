# Разбор: как делали

## Порядок работы

1. **Постановка.** Разобрал задание на 4 обязательных сценария и зафиксировал стек: FastAPI, PostgreSQL + SQLAlchemy + Alembic, aiogram, uv, Docker Compose. Выбрал способ подключения «обычного Telegram»: официальный Telegram Business (бот получает `business_message`) вместо userbot, чтобы всё работало на одном aiogram и в рамках правил Telegram.
2. **Модель данных и архитектура.** Модули `tags` и `leads`, в каждом слои model → repository → service → router. Инфраструктура лежит в `core`. Ключевое решение: все каналы (API, бот, подключённый аккаунт) создают лидов через один `LeadService`.
3. **Миграции.** Alembic `--autogenerate` на локальном Postgres, затем upgrade → downgrade → upgrade и `alembic check` (дрейфа схемы нет).
4. **Telegram.** Анкета на FSM, middleware «одна транзакция на апдейт», обработчик business-сообщений, который отсекает исходящие сообщения владельца.
5. **Тесты.** API, авторизация, группировка сообщений в одного лида, полный диалог с ботом через настоящий `Dispatcher` с подменённой сессией Telegram. Прогон на SQLite и на Postgres.
6. **Веб-интерфейс.** Одна страница на чистом JS, без сборки. Проверено в браузере: создание лида, фильтр по тегу, карточка, история сообщений.
7. **Docker.** Dockerfile на uv (слой зависимостей кэшируется по `uv.lock`) и compose: `db` → `migrate` → `api` + `bot`. Стек собран и поднят локально, проведён smoke-тест.

## Что сделал бы за ещё одну неделю

1. **Ответ клиенту из карточки лида** через Business API (`send_message` с `business_connection_id`), чтобы переписка была в CRM целиком.
2. **Уведомления** о новом лиде в чат менеджеров и **назначение ответственного**; пользователи и роли вместо одной общей учётки.
3. **Канбан по статусам** с drag-n-drop, комментарии и напоминания «перезвонить».
4. **Redis для FSM**, webhook вместо polling, CI (pytest + ruff + сборка образа), бэкапы Postgres.
5. **Аналитика:** конверсия по источникам и тегам, время первого ответа.
6. **Альтернативное подключение аккаунта без Premium** (Telethon) — за тем же интерфейсом сервиса приёма лидов.
